# 🛡️ End-to-End DNSSEC Implementation & Chain of Trust Validation

A hands-on implementation and security validation lab demonstrating the configuration of **Domain Name System Security Extensions (DNSSEC)**. This project establishes cryptographic integrity, authenticity, and a complete hierarchical **Chain of Trust** across an external registrar (**Namecheap**) and an authoritative DNS provider (**AWS Route 53**).

---

## 📌 Architecture & Chain of Trust Flow

DNSSEC mitigates critical DNS threats like **DNS Spoofing**, **Cache Poisoning**, and **Man-in-the-Middle (MitM)** by signing DNS resource record sets (RRsets) with public-key cryptography:

1. **Root Zone (`.`)** holds and signs the DS Record of the TLD via the global Trust Anchor.
2. **TLD Registry (`.site`)** hosts the verified **Delegation Signer (DS) Record** linking to our domain's Key Signing Key (KSK).
3. **Domain Registrar (Namecheap)** relays the DS Record parameters to the parent registry via the EPP protocol.
4. **Authoritative Zone (AWS Route 53)** signs the zone using:
   - **KSK (Key Signing Key):** Signs the `DNSKEY` RRset.
   - **ZSK (Zone Signing Key):** Signs zone resource records (such as `A` Records) generating the `RRSIG`.

---

## 🛠️ Tech Stack & Prerequisites

* **Authoritative DNS Provider:** AWS Route 53
* **Domain Registrar:** Namecheap
* **Target Domain:** `bittco.site`
* **Cryptographic Algorithms:**
  * **Signing Algorithm:** Algorithm 13 (`ECDSA P-256 with SHA-256`)
  * **Digest Type:** Type 2 (`SHA-256`)
* **Verification Tools:** PowerShell (`Resolve-DnsName`), Cloudflare Resolver (`1.1.1.1`)

## 🔍 Validation & Verification

### Step 4: Verify Resource Record Signature (`RRSIG`)
Executed a DNSSEC-aware query against the domain to confirm that the `A` record RRset includes a valid cryptographic signature:

🎯 Key Takeaways & Security Impact
Data Authenticity: The resolver independently validates that records originate strictly from the authorized zone owner.

Data Integrity: Any unauthorized modification of the IP address in transit breaks the cryptographic signature, preventing cache poisoning.

Authenticated Denial of Existence: Uses authenticated cryptographic proofs to ensure non-existent domains cannot be spoofed.
